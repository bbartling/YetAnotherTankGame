Hidden Ball Tank: Three Possible Directions

Goal: keep the good rolling-ball physics, hide the ball, and make the visible tank feel like it is driving.

A

Prototype In BallDriveTest Only

Hide BallDriveTestPlayer renderer, add a tank visual child that follows the ball, and modify ball input so A/D yaw the intended tank heading while W/S roll the ball forward/back.

Pros

  • Fastest, safest validation.
  • No WAR scene regression.
  • Keeps the exact ball Rigidbody setup.

Cons

  • Not yet wired into combat/practice scenes.
B

Shared Hidden-Ball Tank Controller

Create a reusable controller for BallDriveTest, Driving Practice, Cannon Practice, and WAR. The visible tank rides on an invisible sphere body everywhere.

Pros

  • Direct path to replacing the old tank drive stack.
  • One shared model if it works.

Cons

  • Bigger blast radius.
  • Must reconcile combat, camera, rollover, projectile, and enemy assumptions.
C

Hybrid Adapter

Keep existing tank object hierarchy for combat, but move/drive it through a hidden ball proxy. Useful later, but heavier than needed for the first feel test.

Pros

  • Could preserve existing turret/projectile contracts.

Cons

  • More complex coupling.
  • Harder to know whether ball feel is actually the win.

Recommended First Step

Start with A: a deliberately small prototype in BallDriveTest. If the feel is right, promote the pattern into shared gameplay scenes in a later checkpoint.
